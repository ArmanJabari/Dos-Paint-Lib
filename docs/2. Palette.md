# Introduction

In VGA graphics programming—particularly within Mode 13h—managing color is inseparable from understanding the **Color Lookup Table (CLUT)**, commonly referred to as the **VGA Palette** or **DAC (Digital-to-Analog Converter)** palette.

In 256-color modes, a single pixel in memory does not contain raw red, green, and blue values. Instead, each byte represents an index (from 0 to 255) pointing to an entry in the hardware palette. Each palette entry defines a specific color using 6-bit intensity levels for Red, Green, and Blue (RGB).

This document explores the history, architecture, hardware mechanics, color math, and cultural impact of VGA palettes, as well as their implementation in **Dos-Paint-Lib** through SetColor and SetPalette aliases, accompanied by examples and helper tools.

## The Hardware Architecture of the VGA Palette

To understand how colors are rendered in Mode 13h, it is necessary to examine the hardware components responsible for video generation:

1. **Video Memory (VRAM):** Stores byte values (0–255) for each of the 320×200 pixels.
2. **RAMDAC (Random Access Memory Digital-to-Analog Converter):** Reads byte values from VRAM, uses them to look up 6-bit RGB values in internal registers, and converts those digital signals into analog voltages for the CRT monitor.

Because the RAMDAC registers use **6 bits per primary color channel**, each component (Red, Green, Blue) ranges from 0 (off) to 63 (maximum intensity). This provides 2⁶ = 64 levels of brightness per channel, resulting in a theoretical pool of:

**64 × 64 × 64 = 262,144 possible colors**

From this total palette of 262,144 colors, any 256 colors can be active simultaneously on the screen at any given moment.

## Palette Registers and Hardware I/O Ports

In the IBM PC/AT and VGA hardware architecture, the palette registers are modified by communicating directly with the RAMDAC via hardware I/O ports or through BIOS services. The primary hardware I/O ports used for VGA color manipulation are:

| Port Address | Hardware Function        | Purpose                                                |
| ------------ | ------------------------ | ------------------------------------------------------ |
| 0x03C8       | **DAC Write Index Port** | Specifies which palette index (0–255) to write to.     |
| 0x03C9       | **DAC Data Port**        | Accepts consecutive Red, Green, and Blue 6-bit values. |
| 0x03C7       | **DAC Read Index Port**  | Specifies which palette index (0–255) to read from.    |

When writing to 0x03C9, the RAMDAC automatically increments its internal channel pointer after receiving three consecutive byte writes (Red → Green → Blue), automatically advancing to the next color index.

## Palette Manipulation in History and Culture

The ability to change hardware palette entries dynamically in real time gave DOS-era game developers and demoscene programmers immense visual power without incurring heavy CPU overhead.

### Key Historical Palette Techniques

* **Palette Cycling (Color Cycling):** By continuously shifting color values across a subset of palette entries without altering video memory, developers created animated water flows, waterfalls, glowing torches, force fields, and scrolling backgrounds.
* **Fade-In and Fade-Out Effects:** By gradually scaling all palette RGB values toward 0 (black) or 63 (white), full-screen fade transitions were achieved instantly across the entire 320×200 viewport.
* **Palette Flashing / Screen Shakes:** Temporarily remapping the palette (e.g., setting the background index to bright red) provided instant visual feedback for damage, explosions, or lightning strikes.
* **Raster Bars & Copper Effects:** Popularized by the demoscene, changing palette registers in mid-frame (synchronized with the CRT monitor's horizontal refresh) allowed rendering hundreds of colors per frame across scanlines.

## The Default VGA Palette

When InitVGA is executed, the VGA BIOS loads a default set of 256 colors into the RAMDAC.

This legacy layout contains:

1. **Colors 0–15:** Standard 16 CGA/EGA compatible colors (Black, Blue, Green, Cyan, Red, Magenta, Brown, Light Gray, Dark Gray, Light Blue, etc.).
2. **Colors 16–31:** A 16-shade grayscale ramp.
3. **Colors 32–247:** A structured set of color ramps with varying hues, saturations, and brightness levels.
4. **Colors 248–255:** Additional shades and system color definitions.

While useful for basic text and simple graphics, custom applications, game engines, and paint software almost always overwrite this default table with custom palettes tailored to specific artwork.

## Palette Management in Dos-Paint-Lib

**Dos-Paint-Lib** provides two primary assembly interfaces to manipulate the VGA palette easily: modifying individual color entries with SetColor or loading an entire 768-byte color palette array at once with SetPalette.

### Modifying Single Colors: SetColor

The SetColor command is used when fine-grained control over a specific palette index is needed—such as altering a background color, updating a highlight index, or executing color cycling on a limited range of entries.

## Syntax & Parameters

`SetColor index, r, g, b`

* **index:** Byte value or register (0 to 255) specifying the color index to alter.
* **r:** Red intensity level (0 to 63).
* **g:** Green intensity level (0 to 63).
* **b:** Blue intensity level (0 to 63).

**Note:** Color channel values must strictly be within the 6-bit range (0 to 63). Values exceeding 63 (such as standard 8-bit color values 0–255) must be converted before passing to SetColor.

### Example: Setting Index 10 to Bright Yellow

```asm
; Set color index 10 to Bright Yellow
SetColor 10, 63, 63, 0
```

## Modifying the Complete Palette: SetPalette

When loading artwork, changing game screens, or applying full-screen visual filters, updating individual color registers one-by-one is inefficient. The SetPalette procedure updates all 256 colors in a single bulk transaction.

### Palette Data Structure

A valid SetPalette buffer consists of **768 contiguous bytes** stored in memory, arranged as sequential R, G, B triplets for indices 0 through 255:

**Buffer Size = 256 entries × 3 bytes = 768 bytes**

```text
Offset 000: Index 000 Red (0-63)
Offset 001: Index 000 Green (0-63)
Offset 002: Index 000 Blue (0-63)
Offset 003: Index 001 Red (0-63)
Offset 004: Index 001 Green (0-63)
Offset 005: Index 001 Blue (0-63)
...
Offset 765: Index 255 Red (0-63)
Offset 766: Index 255 Green (0-63)
Offset 767: Index 255 Blue (0-63)
```

## Syntax & Parameters

`SetPalette palette_ptr`

* **palette_ptr:** Pointer or label to the 768-byte array containing the RGB values in memory.

## Example: Defining Palette Data

```asm
custom_palette:
    db 0, 0, 0        ; Index 0: Black
    db 63, 0, 0       ; Index 1: Pure Red
    db 0, 63, 0       ; Index 2: Pure Green
    db 0, 0, 63       ; Index 3: Pure Blue
    ; ... (remaining 252 RGB triplets)
    db 63, 63, 63     ; Index 255: White
```

## Palette Helper Tools

Dos-Paint-Lib includes command-line tools in the `tools/` directory to help you prepare color values and convert image palettes into assembly-ready files.

### tools/colorconv.c — RGB Channel Converter

Use this tool to convert standard 8-bit RGB color values (0 to 255) into 6-bit VGA DAC values (0 to 63) for SetColor.

#### How to Use

After building the project with the Makefile, the `colorconv` executable is available in the `build/` directory.

Linux: `./build/colorconv <R> <G> <B>`

Windows: `build/colorconv.exe <R> <G> <B>`

#### Example

Linux: `./build/colorconv 255 128 0`

Windows: `build/colorconv.exe 255 128 0`

**Output:**

```text
63, 32, 0
```

You can use the output directly in your assembly code:

```asm
SetColor 15, 63, 32, 0
```

### tools/palconv.c — Palette File Converter

Use this tool to convert an image file into an assembly include file (`.inc`) containing a 768-byte palette table ready for SetPalette.

#### Supported Formats

* `.bmp` (24-bit image, exactly 16×16 pixels)
* `.pcx` (8-bit or 24-bit image, exactly 16×16 pixels)

#### How to Use

After building the project with the Makefile, the `palconv` executable is available in the `build/` directory.

Linux: `./build/palconv <image_file.bmp | image_file.pcx>`

Windows: `build/palconv.exe <image_file.bmp | image_file.pcx>`

#### Example

Linux: `./build/palconv palette1.bmp`

Windows: `build/palconv.exe palette1.bmp`

#### Output Location

The tool automatically creates a `.inc` file inside `/assets/palettes/` (or `./assets/palettes/`) using the image name as the assembly label:

```text
Success: palette1.bmp -> ./assets/palettes/palette1.inc
```

## How to Use the Generated File in Assembly

Place the include directive at the end of your assembly file, and call SetPalette with the generated label:

```asm
SetPalette palette1

; ... (rest of program code) ...

%include "assets/palettes/palette1.inc"
```

## Program Lifecycle with Palette Initialization

A typical program utilizing Dos-Paint-Lib initializes Mode 13h, sets up custom color schemes or loads external palette files, performs drawing operations, and safely terminates.

```asm
InitVGA

SetPalette custom_palette

SetColor 255, 32, 32, 32

ExitVGA
```
