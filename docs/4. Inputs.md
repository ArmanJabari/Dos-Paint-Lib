# Introduction

Interactive DOS applications and graphical software require responsive, low-latency user input mechanics. In the real-mode x86 DOS environment, input processing is handled without high-level operating system event loops, message pumps, or windowing frameworks. Instead, applications communicate directly with the PC BIOS keyboard services and the resident mouse driver interface.

Handling input within VGA Mode 13h presents unique constraints. Screen refresh timing, coordinate scaling between text/virtual grids and physical pixels, and cursor rendering artifacts all require dedicated management.

This document details the mechanics, hardware interrupts, state handling, coordinate systems, and custom cursor rendering methods in **Dos-Paint-Lib**, covering `keyboard.inc` and `mouse.inc`.

---

## The PC Input Subsystem

In the PC/AT architecture, user input flows across two primary interrupt vectors:

- **BIOS Keyboard Services (INT 16h)** — Interfaces with the keyboard controller (Intel 8042) and the BIOS keyboard circular buffer located in the BIOS Data Area (BDA).
- **Microsoft Mouse Driver Interface (INT 33h)** — Provides a standardized API exposed by installed mouse drivers (such as `MOUSE.COM` or `CTMOUSE.EXE`) to track pointer coordinates, monitor button transitions, and control hardware cursor display.

## Keyboard Input Architecture (`keyboard.inc`)

The keyboard module provides blocking pauses, non-blocking polling, and condition evaluation macros.

### Hardware Mechanics: Scan Codes vs. ASCII

When a physical key is pressed, the keyboard controller sends a serial make code across I/O port `0x60`, triggering `INT 09h`. The BIOS service converts this raw hardware event into a two-byte packet inside the circular keyboard buffer:

- **Low Byte (AL)**: ASCII Character Code (interprets shift states and character values).
- **High Byte (AH)**: BIOS Hardware Scan Code (identifies the physical key position regardless of character mapping, essential for navigation keys).

### Common BIOS Scan Codes (AH)

| Key | Hex Scan Code | Key | Hex Scan Code |
|---|---|---|---|
| Arrow Up | 48h | Escape | 01h |
| Arrow Down | 50h | Enter | 1Ch |
| Arrow Left | 4Bh | Space | 39h |
| Arrow Right | 4Dh | Backspace | 0Eh |

### Keyboard Commands

#### WaitKey

`WaitKey` halts execution until a key is pressed.

**Architectural Mechanics**

The macro invokes the internal procedure `_WaitKey`, which issues `INT 16h, AH=00h`. This halts the CPU until a keystroke appears in the keyboard buffer, consumes it, and returns the key data in the accumulator.

**Syntax & Parameters**

```
WaitKey
```

- Parameters: None.
- Returns: `AL` = ASCII character code, `AH` = BIOS hardware scancode.
- Clobbers: `AX`.

**Example**

```asm
WaitKey                 ; Pause program execution until user presses any key
cmp al, 13              ; Check if Enter was pressed (ASCII 13)
je start_game
```

#### GetKey

`GetKey` performs a non-blocking check on the keyboard buffer.

**Architectural Mechanics**

The macro invokes `_GetKey`, which first calls `INT 16h, AH=01h` to inspect the buffer status without removing entries. If the Zero Flag (ZF) is set, the buffer is empty; the routine clears `AX` via `xor ax, ax` and returns immediately. If a key is present, it issues `INT 16h, AH=00h` to read and remove it from the buffer, returning its codes in `AX`.

**Syntax & Parameters**

```
GetKey
```

- Parameters: None.
- Returns: `AX` = key data (`AL` = ASCII, `AH` = scancode), or `AX` = `0000h` if no key is pending.
- Clobbers: `AX`.

**Example**

```asm
main_loop:
    GetKey              ; Non-blocking poll
    test ax, ax         ; Is a key pending?
    jz render_frame     ; No key pressed; continue loop
    cmp ah, 01h         ; Escape scancode pressed?
    je exit_loop
render_frame:
    ; ... rendering code ...
    jmp main_loop
exit_loop:
```

#### IfKey

`IfKey` tests if the character code in `AL` matches an expected key code and branches if equal.

**Architectural Mechanics**

Expands inline to an 8-bit comparison (`cmp al, key`) followed by a conditional jump (`je label`).

**Syntax & Parameters**

```
IfKey key, label
```

- `key`: Immediate 8-bit value (ASCII code or character literal).
- `label`: Assembly code label to jump to upon a match.

**Example**

```asm
GetKey
IfKey 27, quit_app      ; Jump to quit_app if Escape (ASCII 27) was pressed
IfKey ' ', fire_laser   ; Jump to fire_laser if Spacebar was pressed
```

#### IfNotKey

`IfNotKey` tests if the character code in `AL` differs from an expected key code and branches if not equal.

**Architectural Mechanics**

Expands inline to `cmp al, key` followed by a conditional jump (`jne label`).

**Syntax & Parameters**

```
IfNotKey key, label
```

- `key`: Immediate 8-bit value (ASCII code or character literal).
- `label`: Assembly code label to jump to when values do not match.

**Example**

```asm
GetKey
IfNotKey 'y', skip_confirm  ; Jump to skip_confirm if the pressed key is NOT 'y'
call format_canvas
skip_confirm:
```

## Mouse Input Architecture (`mouse.inc`)

The mouse module provides hardware driver initialization, position tracking, button detection, and software cursor rendering.

### Coordinate Mapping in Mode 13h

Historically, the `INT 33h` driver architecture was developed around CGA and EGA text/graphics resolutions, standardizing its internal horizontal virtual coordinate space to 0–639, even in 320-pixel modes.

Because VGA Mode 13h has a physical resolution of 320×200, the horizontal coordinate reported by `INT 33h, Function 0003h` is scaled by a factor of 2. `_GetMouse` corrects this automatically by shifting the raw `CX` coordinate right by 1 bit (`shr cx, 1`).

### Mouse Buttons Bitmask (BX)

When `GetMouse` returns, `BX` encodes the active physical button states:

- Bit 0 (`0001b`): Left button down
- Bit 1 (`0010b`): Right button down
- Bit 2 (`0100b`): Middle button down

### Cursor Visibility & Framebuffer Safety

The default DOS mouse driver draws and erases a cursor bitmap directly on the display buffer. Drawing graphics primitives while the hardware cursor is visible causes visual artifacting, dirty-pixel remnants, and corrupted framebuffers.

> **Crucial Rule:** Always invoke `HideMouse` prior to executing drawing or blitting operations, and restore it with `ShowMouse` once rendering completes.

### Mouse Commands

#### InitMouse

`InitMouse` initializes the mouse driver interface and verifies hardware presence.

**Architectural Mechanics**

Executes `INT 33h, AX=0000h`. The resident driver resets pointer parameters to screen defaults and returns an installation status code in `AX`.

**Syntax & Parameters**

```
InitMouse
```

- Parameters: None.
- Returns: `AX` = `FFFFh` if mouse hardware and driver are available, `AX` = `0000h` if no driver is found.
- Clobbers: `AX`.

**Example**

```asm
InitMouse
cmp ax, 0FFFFh          ; Verify mouse driver is installed
jne mouse_error         ; Abort or fallback if no mouse detected
```

#### ShowMouse

`ShowMouse` displays the mouse cursor on screen, supporting either driver-managed or custom software cursors.

**Architectural Mechanics**

1. Checks the internal flag `_mouse_visible`. If already marked visible (1), it bypasses redundant standard calls and executes the custom cursor path if active.
2. Sets `_mouse_visible = 1`.
3. If custom cursor mode (`_mouse_is_custom == 1`) is enabled, it bypasses the BIOS driver display function entirely. Instead, it preserves registers via `pusha`, obtains pointer coordinates, applies hotspot offsets, and draws the cursor via `RenderSprite`.
4. If standard mode is enabled, it issues `INT 33h, AX=0001h` to increment the driver's internal visibility counter.

**Syntax & Parameters**

```
ShowMouse
```

- Parameters: None.
- Clobbers: Depends on cursor mode (`AX` for standard driver cursor; registers preserved via `pusha`/`popa` during custom rendering).

**Example**

```asm
ShowMouse               ; Make cursor visible on screen
```

#### HideMouse

`HideMouse` hides the active mouse cursor to ensure safe framebuffer drawing.

**Architectural Mechanics**

1. Clears `_mouse_visible` to 0.
2. Checks `_mouse_is_custom`. If using a custom cursor, it exits immediately, leaving the sprite to be overwritten during subsequent redraw operations.
3. If using the standard driver cursor, it issues `INT 33h, AX=0002h` to decrement the driver's internal visibility counter, safely removing the hardware cursor from video memory.

**Syntax & Parameters**

```
HideMouse
```

- Parameters: None.
- Clobbers: `AX` (standard driver cursor).

**Example**

```asm
HideMouse               ; Hide cursor before drawing
DrawPixel cx, dx, 15    ; Plot pixel without visual artifacts
ShowMouse               ; Restore cursor
```

#### GetMouse

`GetMouse` polls current pointer coordinates and button depression states.

**Architectural Mechanics**

Calls `INT 33h, AX=0003h` to retrieve raw hardware coordinates (`CX` = virtual X, `DX` = physical Y) and button bits (`BX`). It then executes `shr cx, 1` to scale the horizontal coordinate from the virtual 0–639 space down to the physical 0–319 VGA grid.

**Syntax & Parameters**

```
GetMouse
```

- Parameters: None.
- Returns:
  - `BX` = Button status bitmask (Bit 0: Left, Bit 1: Right, Bit 2: Middle).
  - `CX` = Horizontal coordinate (0 to 319).
  - `DX` = Vertical coordinate (0 to 199).
- Clobbers: `AX`, `BX`, `CX`, `DX`.

**Example**

```asm
GetMouse
test bx, 1              ; Test Bit 0 (Left Click)
jz no_click
; CX and DX now hold accurate (X, Y) pixel coordinates
DrawPixel cx, dx, 4     ; Draw red pixel at click location
no_click:
```

#### SetMouseIcon (Solid Cursor)

`SetMouseIcon offset, hx, hy` configures a solid 16×16 custom cursor sprite with hotspot alignment.

**Architectural Mechanics**

1. Preserves `AX` on the stack.
2. Stores the 16×16 sprite buffer address into `_mouse_offset`.
3. Stores `hx` and `hy` into `_mouse_hx` and `_mouse_hy`.
4. Sets `_mouse_is_custom = 1` and disables color keying (`_mouse_has_key = 0`).
5. Restores `AX`.

When `ShowMouse` renders this cursor, it executes `RenderSprite cx, dx, 16, 16, si`, rendering all 256 pixels opaque.

**Syntax & Parameters**

```
SetMouseIcon offset, hx, hy
```

- `offset`: Memory address or label of the 256-byte (16×16) sprite pixel array.
- `hx`: Horizontal hotspot pixel offset relative to the sprite's top-left corner.
- `hy`: Vertical hotspot pixel offset relative to the sprite's top-left corner.

**Example**

```asm
; Solid arrow cursor with top-left hotspot
SetMouseIcon arrow_sprite, 0, 0
ShowMouse
```

#### SetMouseIcon (Transparent Cursor)

`SetMouseIcon offset, hx, hy, color_code` configures a 16×16 custom cursor sprite with transparency keying.

**Architectural Mechanics**

1. Preserves `AX` on the stack.
2. Stores the sprite buffer address into `_mouse_offset`.
3. Stores `hx` and `hy` into `_mouse_hx` and `_mouse_hy`.
4. Stores `color_code` into `_mouse_color_key`.
5. Sets `_mouse_is_custom = 1` and enables color keying (`_mouse_has_key = 1`).
6. Restores `AX`.

When `ShowMouse` renders this cursor, it executes `RenderSprite cx, dx, 16, 16, si, al`, bypassing pixels matching `color_code` so background elements remain visible.

**Syntax & Parameters**

```
SetMouseIcon offset, hx, hy, color_code
```

- `offset`: Memory address or label of the 256-byte (16×16) sprite pixel array.
- `hx`: Horizontal hotspot offset (e.g., 7 for center alignment).
- `hy`: Vertical hotspot offset (e.g., 7 for center alignment).
- `color_code`: Palette color index (0 to 255) treated as fully transparent.

**Example**

```asm
; Crosshair cursor with center hotspot (7, 7) and color 0 as transparent
SetMouseIcon crosshair_sprite, 7, 7, 0
ShowMouse
```

## Interactive Application Lifecycle

The typical lifecycle of an interactive graphical DOS tool integrates display initialization, input detection, drawing operations, and clean resource shutdown:

```asm
InitVGA                     ; Enter 320x200 256-color mode
InitMouse                   ; Initialize mouse driver interface

; Configure custom cursor with color 0 as transparent
SetMouseIcon cursor_arrow, 0, 0, 0
ShowMouse

event_loop:
    GetKey                  ; Non-blocking keyboard check
    IfKey 27, exit_app      ; Exit on ESC (ASCII 27)

    GetMouse                ; Poll coordinates and buttons
    test bx, 1              ; Test left mouse button
    jz event_loop

    ; Handle drawing interaction
    HideMouse               ; Hide cursor before drawing to prevent corruption
    DrawPixel cx, dx, 14    ; Plot yellow pixel at cursor position
    ShowMouse               ; Restore cursor display

    jmp event_loop

exit_app:
    HideMouse               ; Hide cursor before exit
    ExitVGA                 ; Restore text video mode
```

## Dos-Paint-Lib Input Module at a Glance

| Command / Macro | Module | Low-Level Interrupt / Mechanism | Description / Output |
|---|---|---|---|
| WaitKey | Keyboard | `INT 16h, AH=00h` | Blocks CPU until keypress; returns `AL` = ASCII, `AH` = Scancode |
| GetKey | Keyboard | `INT 16h, AH=01h` + `AH=00h` | Non-blocking poll; returns `AX` = key data or `0000h` |
| IfKey | Keyboard | `cmp al, imm8` + `je` | Jump if `AL` matches specified key |
| IfNotKey | Keyboard | `cmp al, imm8` + `jne` | Jump if `AL` does not match specified key |
| InitMouse | Mouse | `INT 33h, AX=0000h` | Resets driver; `AX` = `FFFFh` (detected) or `0000h` |
| ShowMouse | Mouse | `INT 33h, AX=0001h` / Custom | Displays driver cursor or blits 16×16 sprite |
| HideMouse | Mouse | `INT 33h, AX=0002h` / Custom | Hides driver cursor to protect framebuffer |
| GetMouse | Mouse | `INT 33h, AX=0003h` + `shr cx, 1` | Returns `BX` = Buttons, `CX` = X (0–319), `DX` = Y (0–199) |
| SetMouseIcon (Solid) | Mouse | Internal state + `RenderSprite` | Loads 16×16 solid cursor and hotspot offsets |
| SetMouseIcon (Transparent) | Mouse | Internal state + `RenderSprite` | Loads 16×16 cursor, hotspot offsets, and color key |
