# Introduction

In VGA Mode 13h, software rendering relies entirely on direct pixel manipulation within linear video memory. Unlike modern hardware-accelerated pipelines with native vector units, DOS graphics routines must calculate and map geometric primitives byte-by-byte into the frame buffer.

The foundation of any 2D software renderer begins with the individual pixel, expanding outward into horizontal spans, vertical columns, arbitrary slope lines, axis-aligned rectangles, symmetric circles, and arbitrary vertex-connected polygons.

This document details the mechanics, mathematical algorithms, memory-access strategies, and implementation details of the drawing primitives in **Dos-Paint-Lib**, covering `pixel.inc`, `horizontal.inc`, `vertical.inc`, `angled.inc`, `rect.inc`, `circle.inc`, and `polygon.inc`.

---

## Linear Addressing and Offset Computation

Mode 13h uses a linear frame buffer configured at segment `0xA000` with dimensions of 320×200 pixels. Because each pixel occupies exactly 1 byte, calculating the target memory address requires mapping two-dimensional Cartesian coordinates (X, Y) into a one-dimensional byte offset:

```
Offset = (Y * 320) + X
```

Across the primitive routines, the library relies on an internal helper:

```asm
call _GetVGAOffset  ; Returns DI = (Y * 320) + X
```

All drawing primitives assume that ES is pre-loaded with the VGA video memory segment `0A000h` (typically handled during `InitVGA`).

## 1. Single Pixel Drawing (`pixel.inc`)

The most fundamental primitive in software graphics is plotting an isolated color index directly to an (X, Y) coordinate.

### Architectural Mechanics

Writing a pixel requires computing the linear byte offset and performing an 8-bit store to `[es:di]`:

1. Compute `DI = (Y * 320) + X`.
2. Move the 8-bit color index into `[es:di]`.

### Syntax & Parameters

```
DrawPixel x, y, color_code
```

- `x`: Horizontal screen coordinate (0 to 319).
- `y`: Vertical screen coordinate (0 to 199).
- `color_code`: Byte palette index (0 to 255).

### Example

```asm
DrawPixel 160, 100, 15     ; Plot a white pixel at screen center
DrawPixel 10,  10,  4      ; Plot a red pixel at (10, 10)
```

## 2. Horizontal Lines (`horizontal.inc`)

Drawing a horizontal line is a sequential memory operation. Because pixels along the same scanline lie contiguously in video memory, horizontal lines can bypass point-by-point offset recalculation entirely.

### Architectural Mechanics & Hardware Acceleration

Rather than using manual loop counters, `DrawHLine` leverages the x86 string manipulation instruction `rep stosb`:

1. The Direction Flag is cleared (`cld`) to guarantee forward address increments.
2. `AL` is populated with the color byte.
3. `CX` is loaded with the line length (number of pixels).
4. `rep stosb` writes `AL` into `[es:di]` and increments `DI` on every cycle until `CX` reaches 0.

This maximizes memory bus throughput on x86 processors and forms the primary building block for rasterizing filled shapes.

### Syntax & Parameters

```
DrawHLine x, y, color_code, length
```

- `x`: Starting horizontal coordinate.
- `y`: Scanline row.
- `color_code`: Byte palette index (0 to 255).
- `length`: Span length in pixels.

### Example

```asm
DrawHLine 10, 50,  12, 200   ; 200px red horizontal line at Y=50
DrawHLine 10, 100, 14, 150   ; 150px yellow horizontal line at Y=100
```

## 3. Vertical Lines (`vertical.inc`)

Unlike horizontal lines, vertical lines traverse non-contiguous memory. Moving down one pixel in the same column requires advancing exactly one full scanline stride (320 bytes).

### Architectural Mechanics

1. Calculate the initial base offset via `_GetVGAOffset` into `DI`.
2. Write the color byte `BL` into `[es:di]`.
3. Add 320 to `DI` to step to the next row directly beneath the current pixel.
4. Decrement the pixel counter (`CX`) and repeat until zero.

### Syntax & Parameters

```
DrawVLine x, y, color_code, length
```

- `x`: Column coordinate.
- `y`: Starting vertical coordinate.
- `color_code`: Byte palette index (0 to 255).
- `length`: Span height in pixels.

### Example

```asm
DrawVLine 50, 10, 10, 180    ; Green vertical line at X=50, 180px tall
DrawVLine 80, 20, 11, 100    ; Cyan vertical line at X=80, 100px tall
```

## 4. Angled Lines (`angled.inc`)

Connecting two arbitrary points (X0, Y0) and (X1, Y1) requires rasterizing an angled segment. Floating-point vector math is too slow for 16-bit real-mode DOS graphics, so Dos-Paint-Lib implements Bresenham's Line Algorithm using pure integer arithmetic.

### The Integer Bresenham Algorithm

Bresenham's algorithm determines the closest pixel grid approximation along a continuous vector using an accumulated error term. By doubling the error comparison (2 × err), the entire trajectory is computed using only additions, subtractions, and bitwise shifts:

1. **Delta Calculation** — Determine absolute horizontal (ΔX) and vertical (ΔY) distances.
2. **Step Offsets** — Set `sx_off` to +1 or -1 for horizontal movement, and `sy_off` to +320 or -320 for vertical movement.
3. **Decision Parameter** — Initialize `err = ΔX - ΔY`.
4. **Loop Traversal** — At each iteration, plot the pixel at `[es:di]` and evaluate `e2 = 2 * err`:
   - If `e2 > -ΔY`, update `err += -ΔY` and increment `DI` by `sx_off`.
   - If `e2 < ΔX`, update `err += ΔX` and increment `DI` by `sy_off`.

### Syntax & Parameters

```
DrawALine x0, y0, x1, y1, color_code
```

- `x0, y0`: Starting coordinates.
- `x1, y1`: Ending coordinates.
- `color_code`: Byte palette index (0 to 255).

### Example

```asm
DrawALine 0, 0,   319, 199, 12   ; Red diagonal line from top-left to bottom-right
DrawALine 0, 199, 319, 0,   15   ; White diagonal line from bottom-left to top-right
```

## 5. Rectangles (`rect.inc`)

`DrawRect` supports both hollow outlines and solid filled boxes through an explicit mode flag.

### Rendering Strategies

**Hollow Mode (`fill = 0`)**
- The top row (first row) and bottom row (last row) are rendered as solid spans using `rep stosb`.
- Interior rows only plot two pixels: the left boundary at `[es:di]` and the right boundary using base-plus-index addressing `[es:bx+di]`, where `bx = width - 1`.
- Advances row by row by adding 320 to `DI`.

**Filled Mode (`fill = 1`)**
- Uses an outer row loop running H times.
- Rapidly blits W contiguous bytes on each scanline using `rep stosb`.
- Advances to the start of the next scanline by adding the stride difference `320 - width` directly to `DI`.

### Syntax & Parameters

```
DrawRect x, y, color_code, width, height, fill
```

- `x, y`: Upper-left origin coordinates.
- `color_code`: Byte palette index.
- `width, height`: Dimensions of the box in pixels.
- `fill`: Mode selector (0 = hollow outline, 1 = filled solid).

### Example

```asm
DrawRect 10,  10,  15, 100, 50, 0    ; White hollow rectangle
DrawRect 50,  50,  12, 80,  40, 1    ; Red filled rectangle
DrawRect 100, 100, 14, 60,  30, 0    ; Yellow hollow rectangle
```

## 6. Circles (`circle.inc`)

Circles are rasterized using the Midpoint Circle Algorithm (Bresenham's circle variant).

### Eight-Way Symmetry and Span Filling

A circle exhibits 8-fold radial symmetry. Evaluating coordinates for a single 45° octant (x ≥ y) yields the remaining seven points by reflection.

**Hollow Circles (`fill = 0`)** — Plots 8 symmetric boundary points per iteration using `_Circle8Points`.

**Filled Circles (`fill = 1`)** — Instead of individual points, `_CircleFillLines` draws 4 horizontal scanlines per iteration connecting symmetrical pairs, filling the interior solid without overdraw:

- Row `Yc + Y` from `Xc - X` to `Xc + X` (width = 2X + 1)
- Row `Yc - Y` from `Xc - X` to `Xc + X` (width = 2X + 1)
- Row `Yc + X` from `Xc - Y` to `Xc + Y` (width = 2Y + 1)
- Row `Yc - X` from `Xc - Y` to `Xc + Y` (width = 2Y + 1)

The decision parameter P initializes to `1 - R` and updates iteratively with additions and shifts.

### Syntax & Parameters

```
DrawCircle x, y, color_code, radius, fill
```

- `x, y`: Circle center coordinates.
- `color_code`: Byte palette index.
- `radius`: Radius in pixels.
- `fill`: Mode selector (0 = hollow outline, 1 = filled).

### Example

```asm
DrawCircle 160, 100, 15, 50, 1      ; White filled circle at center, radius 50
DrawCircle 50,  50,  12, 20, 0      ; Red hollow circle at (50, 50), radius 20
```

## 7. Polygons (`polygon.inc`)

`DrawPoly` draws arbitrary closed hollow polygons by connecting an ordered list of 2D vertices sequentially with `DrawALine`.

### Vertex Array Structure

Vertices are organized in memory as contiguous 16-bit word coordinate pairs (X, Y):

```asm
triangle_pts:
    dw 160, 20      ; Vertex 0: (x0, y0)
    dw 260, 180     ; Vertex 1: (x1, y1)
    dw 60,  180     ; Vertex 2: (x2, y2)
```

### Architectural Mechanics

1. **Validation** — Checks if vertex count ≥ 3 (aborts if fewer).
2. **Origin Retention** — Preserves (X0, Y0) on the stack frame to close the loop later.
3. **Traversal** — Loops through (Vi, Vi+1), calling `DrawALine` for each edge.
4. **Closing Segment** — Draws a final line from the terminating vertex back to (X0, Y0).

### Syntax & Parameters

```
DrawPoly points_ptr, count, color_code
```

- `points_ptr`: Pointer or label to the vertex coordinate array.
- `count`: Total number of vertices (N ≥ 3).
- `color_code`: Byte palette index.

### Example

```asm
DrawPoly triangle_pts, 3, 14        ; Draw yellow triangle
DrawPoly hex_pts,      6, 15        ; Draw white hexagon
```

## Program Lifecycle with Drawing Primitives

The standard operational flow requires initializing VGA Mode 13h, loading palettes or drawing geometric shapes into memory, and restoring the text display upon exit:

```asm
InitVGA

; Draw geometric layout
DrawRect   0,   0,   1, 320, 200, 1    ; Clear screen with color 1 (filled background)
DrawHLine  0,   20,  15, 320           ; Header divider line
DrawVLine  160, 20,  15, 180           ; Center vertical boundary
DrawCircle 80,  110, 12, 40,  1        ; Filled red circle in left pane
DrawRect   180, 70,  10, 80,  80, 0    ; Hollow green square in right pane
DrawPoly   poly_pts, 4,  14            ; Yellow diamond overlay

ExitVGA
```

## Dos-Paint-Lib Draw Module at a Glance

| Primitive | Macro Signature | Core Algorithm / Mechanism | Fill Support |
|---|---|---|---|
| Pixel | `DrawPixel x, y, color` | Direct offset write `[es:di]` | N/A |
| HLine | `DrawHLine x, y, color, length` | `rep stosb` scanline fill | Native (Span) |
| VLine | `DrawVLine x, y, color, length` | Stride addition (`add di, 320`) | N/A |
| Angled Line | `DrawALine x0, y0, x1, y1, color` | Bresenham's Line Algorithm (Integer DDA) | N/A |
| Rectangle | `DrawRect x, y, color, w, h, fill` | `rep stosb` spans + stride skips | Hollow (0) / Filled (1) |
| Circle | `DrawCircle x, y, color, r, fill` | Midpoint Circle Algorithm (8-octant symmetry) | Hollow (8-pt) / Filled (4-span) |
| Polygon | `DrawPoly points_ptr, count, color` | Sequential `DrawALine` edge loops + closure | Hollow |
